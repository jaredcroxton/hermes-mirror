# PerformOS content launch approval and first-preview workflow

Use this reference when Jared asks for a PerformOS content strategy, launch plan, video campaign, or social content system and wants control before execution.

## Approval-first workflow

When Jared wants a full strategy but says not to execute until approval:

1. Build an Excel approval workbook, not a prose-only plan.
2. Include rows that can be marked `Approve`, `Decline`, `Hold`, or `Needs edit`.
3. Include at minimum:
   - Approval Dashboard
   - How to Use
   - Content Strategy Master Plan
   - Video Series Approval
   - Website/Funnel Approval
   - Agent Routing Approval
   - 90 Day Calendar
   - Decision Log
4. Make it clear that only approved rows become action briefs after Jared re-uploads the workbook.
5. Do not start production work until Jared approves specific rows.

## Sub-agent governance

For PerformOS launch/content work, Brock should orchestrate. Specialist agents should produce their lanes.

Default routing:

- Brock: strategy, sequencing, pressure-testing, final synthesis
- Polly_PerformOS: PerformOS / AgentOS positioning, product-state claims, brand safety
- Mira_Creative: visual system, video concepts, captions, thumbnails, first previews
- Serge_SEO: keyword map, SEO cluster, article briefs, internal links
- Bob_Builder: landing pages, web builds, deployable assets, forms
- Nelly_Notebook: source synthesis and grounded briefing packs
- Lara_LearningDesign: learning/workshop crossover
- Harry_HR: HR/legal understanding where specific market/scenario risk exists

If Jared explicitly says to use sub-agents, embed this as a governance tab or routing section in the approval workbook.

## CAL-row first-preview pattern

When Jared approves or selects a row from the 90-day calendar, such as `CAL-002`, do not jump straight into final production.

1. Route to Mira first for a production-ready creative prompt.
2. Ask Mira for:
   - exact generation/production prompt
   - 20-30 second storyboard with timestamps
   - on-screen captions
   - shot list
   - editing style
   - CTA
   - assets needed for a preview without final footage
3. Build a lightweight preview/animatic if possible.
4. Use the preview to judge rhythm, message, captions, structure, and CTA before real filming or high-fidelity generation.
5. Label it clearly as a preview/animatic, not final creative.

## Animatic fallback pattern

If high-fidelity image/video generation is not configured or not worth spending on yet, create a simple animatic instead of stopping:

- vertical 9:16 MP4
- placeholder illustrated or stock-style interviewee frames
- real or synthetic voiceover
- final caption rhythm
- PerformOS end card
- one thumbnail frame
- production brief saved beside the preview

The purpose is decision quality, not final polish.

Do not persist environment-specific failures such as missing keys as durable constraints. Capture the setup fix separately if needed, but the reusable lesson is the preview/animatic pattern.
